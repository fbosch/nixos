# Pi sandbox policy

## Scope and status

This policy describes the Linux Pi launcher generated by `modules/development/ai/pi/default.nix` and the profile in `modules/development/ai/nono/scripts/profile.json`. It does not describe the permissions of an already-running Pi process. Existing processes retain their old grants until they exit.

The persistence decision is **LOCK-DOWN**. The `/proc` finding remains unresolved. This is not a completed sandbox audit.

## Persistence decision: LOCK-DOWN

The Linux launcher makes the default agent directory and the configured `PI_CODING_AGENT_DIR` read-only except for named runtime data. It protects settings, extension code, package installations, supporting libraries, and their symlink targets. The same restrictions apply when those files live in the writable dotfiles repository.

Writable agent data is limited to existing `sessions`, `cache`, `session-history`, `tasks`, `auth-profiles`, and `fff` directories, plus the existing `auth.json` file. The launcher prepares these data directories before confinement. It grants `auth.json` in place without making its parent writable, so normal credential refresh does not authorize configuration replacement. These are Pi's own credentials, not the separately denied `~/.claude/.credentials.json`.

The packaged lockfile library uses `~/.cache/pi/locks` under the launcher's `PI_LOCKFILE_DIR` setting. This lets Pi read its settings and coordinate auth updates without creating lock directories beside protected files. Jiti's writable filesystem compilation cache is disabled with `JITI_FS_CACHE=false`.

A sandbox process cannot approve its own persistent code changes. To update managed resources:

1. Exit Pi sessions before host-side authentication updates. Older permissive sessions must also exit before the new restrictions can be relied on.
2. Review and edit the files, or run the package-management operation, from a host terminal outside Pi's sandbox.
3. If using Bun to install developer dependencies, use `--backend=copyfile --frozen-lockfile`. Shared hard links can expose executable files through writable cache aliases, so the launcher rejects them.
4. Start a new Pi session to load the reviewed resources.

Runtime data remains mutable and can be corrupted by an agent. Arbitrary project files and host-executed development scripts are separate trust boundaries. This change does not make those files trusted, prevent all denial of service, or prevent a host process from modifying Pi's resources.

## Explicit raw launch

A leading `--no-sandbox` replaces the launcher process with raw Pi before sandbox setup. It skips policy and IPC-manifest validation, project-environment loading, sandbox resource checks, helper brokers, diagnostics injection, and credential-proxy startup. Pure agent-directory and PATH normalization still keeps the immutable launcher ahead of writable shims. Raw Pi retains its own normal configuration and authentication requirements.

Raw mode preserves the caller's environment. It does not prepare or impose the sandbox's runtime lock directory. Do not concurrently update the same auth store from raw and confined sessions unless both use the same `PI_LOCKFILE_DIR`.

The flag cannot remove kernel restrictions inherited from an already-sandboxed parent. Invoke raw mode from a host terminal when unrestricted host access is intended.

## Proxy decision: unrestricted forwarding accepted

The owner explicitly accepted unrestricted proxy forwarding for this pass. `example.com` is permitted by the default forwarding policy, not by an individual allowlist entry.

The generating profile has `network.block = false` and no `allow_domain` entries. The standalone proxy uses that profile. The child sandbox receives a separate profile with `network.block = true` and a grant for the proxy port. Consequently, the child's `NONO_CAP_FILE` can show `net_blocked: true` and `allowed_domains: []` while proxy forwarding remains unrestricted.

This deliberately retains an exfiltration channel for data the agent can read. Direct TCP access to ports 22, 80, and 443 remains denied. The existing browser-port exceptions were not changed in this pass.

## Unresolved process metadata

Nono 0.80 widens its `/proc/self` read grant to `/proc` so descendants can read their own process metadata. The requested profile-only fixes did not work:

- `/proc/[0-9]*/cmdline` is rejected because deny globs support only `*` and `**`.
- `/proc/*/cmdline` and `/proc/*/comm` conflict with the self-process read grant. Nono refuses to launch because Landlock cannot subtract those denies from an allowed parent.

No ineffective deny entries were added. The proposed backend change was not approved. `/proc/1/cmdline` and `/proc/1/comm` remain readable; process isolation is still pending.

## Verification

`nono-pi-agent-protection` starts a new native nono sandbox from a Nix check. It uses synthetic credential files, a live fixture SSH-agent socket, and a Stow-style Fish configuration. It tests both the default and configured Pi directories. It also starts the packaged Pi CLI in RPC mode and verifies that an extension selected by the existing settings registers its command. It does not make a model inference request.

| Finding | Before | After and verification | Result |
| --- | --- | --- | --- |
| Pi settings and extensions | Writable parent grants covered the resources. | Append to both settings paths, create an extension directory, and append to existing extension code. | Denied in the fresh fixture sandbox. Existing approved extension loads. |
| Other-process cmdline and comm | Readable through the widened `/proc` grant. | `cat /proc/1/cmdline` and `cat /proc/1/comm`. Expected denial. | Still readable. Not fixed. |
| Own cmdline | Readable. | `cat /proc/self/cmdline`. | Readable as required. |
| Proxy destinations | Unrestricted forwarding; no domain allowlist. | Inspect the generating profile and confirm owner intent. | Unchanged and explicitly accepted. No external proxy GET was repeated in this pass. |
| Direct HTTPS | Previously fixed. | Requested curl probe to `https://ifconfig.me`; separate loopback TCP probes to ports 22, 80, and 443. | Curl returns `000`. The TCP probes return `EACCES`. |
| Direct SSH | Previously fixed. | Bash opens `/dev/tcp/140.82.121.4/22`. | Denied. |
| Claude OAuth file | Previously fixed. | `cat "$HOME/.claude/.credentials.json"` against a real synthetic file. | Denied. |
| SSH agent | Previously fixed by default. | `ssh-add -l` with `SSH_AUTH_SOCK` pointing to the live fixture socket. | Denied. |
| Fish startup file | Previously fixed. | `echo p >> "$HOME/.config/fish/config.fish"` through a Stow symlink. | Denied. |
| Kernel core pattern | Previously denied. | `echo p >> /proc/sys/kernel/core_pattern`. | Denied. |
| Other-process environment | Previously denied. | `cat /proc/1/environ`. | Denied. |

Nix's build network has no external DNS. Curl's `000` alone therefore does not prove the network boundary; the independent TCP probes check the kernel permission error. The fixture paths are not the workstation's live credentials or configuration. Deployment and fresh workstation verification remain separate steps.
